# MyNet Quasar 项目概述

## 📋 项目背景

MyNet Quasar是从原有的MyNet项目（Laravel + Alpine.js）迁移而来的现代化前端应用。原项目采用传统的服务端渲染架构，随着业务需求的增长，需要向现代化的前端架构演进，以支持多平台部署、更好的用户体验和开发效率。

### 迁移原因

1. **技术栈老化**: Alpine.js + Bootstrap的组合在复杂应用中维护困难
2. **多平台需求**: 需要支持Web、桌面和移动端
3. **开发效率**: 需要更好的开发工具和类型安全
4. **用户体验**: 需要更流畅的交互和响应式设计
5. **部署灵活性**: 需要支持纯静态部署和CDN加速

## 🎯 项目目标

### 核心目标
- **多平台支持**: 浏览器（**实际在跑**）· Electron 桌面（**可构建**）· 移动端 WebApp（**未配置**）—— 三者状态差别大，见下方「平台支持」
- **纯静态前端**: 可部署到任何静态文件服务器（本项目实际用主机 nginx，见 `docs/06-部署指南.md`）
- **API数据交互**: 与Laravel后端通过RESTful API通信
- **完整会话管理**: Token自动刷新 + 实时监控平衡
- **多语言支持**: 动态从服务端获取语言包
- **多主题系统**: 动态主题切换
- **框架业务隔离**: 核心框架与业务逻辑完全分离
- **域隔离支持**: 多Zone数据隔离
- **高性能**: 现代化构建工具和优化策略

### 技术目标
- **类型安全**: 全面的TypeScript类型系统
- **组件化**: 高度可复用的组件架构
- **响应式**: 完整的响应式设计
- **国际化**: 完整的多语言支持
- **可测试**: 完善的测试框架
- **可维护**: 清晰的代码结构和文档

### 平台支持
```json
{
  "web": "SPA + PWA",
  "desktop": "Electron",
  "mobile": "Capacitor",
  "static": "Nginx/Apache/CDN"

```

> ⚠️ 上面四项**只有 `web` 与 `static` 是实际在跑的**。另两项 2026-09-24 实测：
>
> | 目标 | 实测结果 |
> |---|---|
> | `desktop`（Electron） | ⚠️ **一条命令能出产物，但仓里并没有配置**：`npm run build:electron` → 退出码 0、`Build succeeded`、产物落 `dist/electron`。⚠️ 关键在于**产物是 Quasar 兜底出来的**：本仓 `package.json` 原本**没有** electron 依赖、也没有 `src-electron/` 目录，这两者都是构建过程中被**自动写进去/生成**的（含 `electron@44.4.5`）。所以这是「Quasar 的 electron 模式能跑」，不等于「本项目配好了桌面端」。另外它**从未发布过**——没有签名/打包分发配置，且首次构建告警缺图标（`Could not find icon … skipping`） |
> | `mobile`（Capacitor） | ❌ **连产物都出不来**：仓里**没有** `@capacitor/*` 依赖、没有 `src-capacitor/`，`package.json` 只有一行 `build:capacitor` 脚本。实测 `npm run build:capacitor -T android` 会停下来**交互索要 appId**——Quasar 的 capacitor 模式不像 electron 那样能自动兜底。要上移动端得先补 `src-capacitor/` |
> | `static` | ✅ 生产即走这条：`deployment.sh` 本地 build + rsync 到主机 nginx（`my.mynet.club`） |
>
> `package.json` 里那两个 `build:electron` / `build:capacitor` 脚本**本身不代表已支持**——
> 判据是「能不能真出产物」，而且还要看**产物是怎么来的**：Electron 那条能出，靠的是
> Quasar 构建时自动补齐（不是本仓的配置）；Capacitor 那条连产物都出不来。

## 🏗️ 架构优势

### 1. 现代化技术栈
- **Vue 3**: 最新的Vue.js版本，提供更好的性能和开发体验
- **TypeScript**: 类型安全，减少运行时错误
- **Quasar**: 丰富的UI组件库，支持多平台
- **Vite**: 快速的构建工具，热重载体验好

### 2. 多平台支持
- **Web**: 标准的SPA应用
- **PWA**: 支持离线使用和推送通知
- **Desktop**: 通过Electron打包成桌面应用
- **Mobile**: 通过Capacitor打包成移动应用

### 3. 架构分离
- **前后端分离**: 前端纯静态，后端纯API
- **框架业务分离**: 核心框架与业务逻辑解耦
- **平台无关**: 一套代码，多平台部署

### 4. 开发效率
- **组件化**: 高度可复用的组件系统
- **类型安全**: TypeScript提供编译时检查
- **热重载**: 开发时即时更新
- **测试友好**: 完整的测试框架支持

## 🚀 部署灵活性

### 静态部署 ★本项目实际采用
- **CDN友好**: 可部署到任何静态文件服务器
- **缓存优化**: 文件hash化，缓存友好
- **压缩支持**: 自动生成压缩文件
- **多环境**: 支持多套环境配置

### 容器化部署 〔未实现 · 别照此规划〕
