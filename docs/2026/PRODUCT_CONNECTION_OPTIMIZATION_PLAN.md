## 🎯 设计理念

### 核心原则

基于 MyNet 产品宣言,本次优化围绕以下核心原则:

1. **连接选择权优先** (P1)
   - 所有设计引导用户"选择连接",而非"拥有网络"
   - 让连接的建立、维护、断开都清晰可见

2. **进入优先于创建** (P3)
   - 用户体验路径: 进入 Zone → 发现节点 → 建立连接
   - 弱化"创建Zone"的引导,强化"加入Village"的体验

3. **显性连接管理** (P7-P9)
   - 连接必须是可见的、可管理的、可撤销的
   - 拒绝连接和建立连接同等重要

### 产品定位调整

**核心原则**: 产品服务于理念，而不是宣扬理念

**从**:一个提供网络空间的工具  
**到**:一个让人与设备自由连接的平台

**关键转变**:
- ❌ 不强调"你的私有网络"
- ✅ 强调"你选择的连接"
- ❌ 不突出"Zone概念" (Zone透明化)
- ✅ 突出"设备之间的连接"
- ❌ 不做公开发现和搜索
- ✅ 基于邀请的信任关系

## 🔄 核心优化策略

### 策略 1: 重构信息架构

**现状问题**:
- 用户登录后首先看到的是技术概念(节点、路由、IP池)
- Dashboard聚焦于设备状态,而非连接状态
- 过度暴露Zone概念，实际Zone应该透明化

**优化方向**:
```
旧架构: Dashboard → 节点 → 路由 → IP池 → Zone
新架构: 连接概览 → 我的设备 → 好友 → 好友的设备 → 建立连接

关键变化:
- Zone仅在顶部切换器 + 退出操作
- 其余操作都在选定Zone内，无需体现Zone
- 连接颗粒度：设备↔设备
- 社交层面：人(账号)→人(账号)
```

### 策略 2: 建立"连接"视角

**连接的层级结构**:
```
人(账号) → 设备(node)
         ↓
    连接颗粒度: 设备↔设备
```

将所有功能模块从"管理"视角转向"连接"视角:

| 旧模块 | 新视角 | 核心价值 |
|--------|--------|----------|
| 节点管理 | 我的设备 | 我有哪些设备可以被连接 |
| 路由管理 | 连接管理 | 我的设备与谁的设备建立了连接 |
| IP池管理 | 资源池(高级) | IP资源分配(技术细节) |
| Zone管理 | 无需管理 | Zone透明化，仅顶部切换+退出 |

### 策略 3: 引导连接发生

在关键节点主动引导用户建立连接:

1. **首次登录**: 引导添加第一个设备
2. **设备添加后**: 引导查看Village中的可连接节点
3. **发现节点后**: 引导建立第一个好友连接
4. **建立连接后**: 引导查看连接质量和管理

## 🚶 用户旅程设计

### 新用户完整旅程

```
Step 1: 获得邀请
├─ 从朋友/组织获得邀请链接或邀请码
├─ 邀请码中已包含Zone信息
└─ 理解: 你将加入邀请人的网络空间

Step 2: 注册并自动加入Zone
├─ 输入邀请码
├─ 填写基本信息(用户名/邮箱/密码)
├─ 激活账户
└─ 自动加入邀请码对应的Zone ✓

Step 3: 添加第一个设备 (引导)
├─ 登录后看到: "欢迎! 添加你的第一个设备开始连接"
├─ 选择设备类型(电脑/手机/服务器/路由器)
├─ 下载客户端 + 配置
└─ 我的设备上线 ✓

Step 4: 添加好友 (引导)
├─ 提示: "添加好友，连接他们的设备"
├─ 通过用户名/邮箱搜索好友(同Zone内)
├─ 发送好友申请
└─ 建立好友关系(人↔人) ✓

Step 5: 查看好友的设备
├─ 进入"好友的设备"页面
├─ 看到好友的在线设备列表
└─ 选择想要连接的设备

Step 6: 建立设备连接 (引导)
├─ 选择: 我的设备A → 好友的设备B
├─ 点击"发起连接"
├─ 等待对方批准(如需)
└─ 设备连接建立 ✓

Step 7: 使用和管理连接
├─ 查看连接状态和质量
├─ 使用连接(文件传输/远程访问)
└─ 随时断开连接

Step 8: 邀请更多好友
├─ 生成邀请链接(包含当前Zone)
├─ 邀请朋友加入
└─ 扩大网络

Step 9: 加入其他Zone(可选)
├─ 收到其他Zone的邀请
├─ 加入新的Zone
├─ 通过顶部切换器在不同Zone间切换
└─ 注意: 退出Zone将失去该Zone内所有连接
```

### 老用户回归旅程

```
登录
├─ 看到连接概览
├─ 检查: 哪些连接仍活跃
├─ 发现: 是否有新的连接请求
├─ 查看: 好友是否有新分享
└─ 快速访问常用连接
```

## � Zone机制在产品中的体现

### Zone的实际运作

**邀请制 + 自动加入**:
```
用户获得邀请码/链接
    ↓
邀请码包含Zone信息
    ↓
注册时自动加入该Zone
    ↓
无需理解Zone概念
```

**Zone在界面中的位置**:

1. **顶部导航栏**:
   - Zone切换器: 在多个Zone间切换
   - 退出按钮: 退出当前Zone(警告: 失去所有连接)

2. **页面内容**:
   - 不显示Zone名称
   - 不提示"你在XX Zone中"
   - 所有操作默认在当前Zone内

3. **连接逻辑**:
   - 只能看到同Zone内的好友
   - 只能连接同Zone内的设备
   - 边界由系统强制执行，用户无感

**多Zone场景**:
```
用户可能加入:
├─ 工作Zone (公司邀请)
├─ 家庭Zone (家人邀请)
└─ 朋友Zone (朋友邀请)

通过顶部切换器:
├─ 切换到"工作" → 看到工作设备和同事
├─ 切换到"家庭" → 看到家庭设备和家人
└─ 切换到"朋友" → 看到朋友设备

每个Zone的连接完全隔离
```

**退出Zone的后果**:
- ⚠️ 失去该Zone内所有连接
- ⚠️ 无法访问该Zone的任何资源
- ⚠️ 无法被该Zone的用户连接
- 需要重新获得邀请才能加入

|------|---------|---------|------|

| 节点 | 设备 | 节点 / Node | 更易理解 |
| 路由 | 连接 | 路由 / Route | 符合用户心智 |
| 建立连接 | 连接 / 发起连接 | 创建路由 | 动词化，强调设备↔设备 |
