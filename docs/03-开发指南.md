# MyNet Quasar 开发指南

## 🚀 快速开始

### 前置要求

- **Node.js**: 18.0.0 或更高版本
- **npm**: 9.0.0 或更高版本
- **Git**: 2.30.0 或更高版本
- **IDE**: 推荐使用 VS Code + Volar 扩展

### 开发环境搭建

1. **克隆项目**
```bash
git clone <repository-url>
cd mynet_quasar
```

2. **安装依赖**
```bash
npm install
```

3. **环境配置**
```bash
# 复制环境配置文件
cp .env.example .env

# 配置API服务地址
# 编辑 .env 文件，设置以下变量：
# VUE_APP_API_URL=http://localhost:8000
# VUE_APP_WS_URL=ws://localhost:8000
```

4. **启动开发服务器**
```bash
npm run dev
```

5. **访问应用**
```
浏览器打开: http://localhost:8080
```

### 2. Vue 组件规范

```vue
<template>
  <!-- 使用 kebab-case 属性 -->
  <div class="user-profile">
    <q-card class="profile-card">
      <!-- 事件处理使用 handle 前缀 -->
      <q-btn @click="handleSubmit">
        {{ $t('common.submit') }}
      </q-btn>
    </q-card>
  </div>
</template>

<script setup lang="ts">
// 1. 导入顺序：Vue API -> 第三方库 -> 本地模块
import { ref, computed, onMounted } from 'vue';
import { useQuasar } from 'quasar';
import { useAuthStore } from '@/stores/auth';

// 2. 接口定义
interface Props {
  userId: string;
  readonly?: boolean;
}

// 3. Props 和 Emits 定义
const props = withDefaults(defineProps<Props>(), {
  readonly: false
});

const emit = defineEmits<{
  submit: [data: UserData];
  cancel: [];
}>();

// 4. 响应式数据
const loading = ref(false);
const formData = ref<UserData>({});

// 5. 计算属性
const isFormValid = computed(() => {
  return formData.value.name && formData.value.email;
});

// 6. 方法定义
const handleSubmit = async () => {
  if (!isFormValid.value) return;
  
  loading.value = true;
  try {
    await submitUserData(formData.value);
    emit('submit', formData.value);
  } catch (error) {
    console.error('Submit failed:', error);
  } finally {
    loading.value = false;
  }
};

// 7. 生命周期钩子
onMounted(() => {
  loadUserData();
});
</script>

<style scoped>
.user-profile {
  padding: 16px;
}

.profile-card {
  max-width: 500px;
}
</style>
```

## 📈 最佳实践

### 1. 组件设计

- **单一职责**: 每个组件只负责一个功能
- **可复用性**: 设计时考虑复用场景
- **可测试性**: 易于编写单元测试
- **可维护性**: 代码结构清晰，易于理解

### 2. 状态管理

- **最小状态**: 只存储必要的状态
- **状态规范化**: 避免嵌套过深的状态结构
- **副作用隔离**: 将副作用集中在 actions 中
- **类型安全**: 使用 TypeScript 确保类型安全

### 3. 错误处理

```typescript
// 全局错误处理
app.config.errorHandler = (error, instance, info) => {
  console.error('Global error:', error);
  console.error('Error info:', info);
  
  // 发送错误报告
  reportError(error, {
    component: instance?.$options.name,
    info
  });
};

// 组件错误边界
const ErrorBoundary = defineComponent({
  name: 'ErrorBoundary',
  setup(props, { slots }) {
    const error = ref<Error | null>(null);
    
    const handleError = (err: Error) => {
      error.value = err;
      console.error('Component error:', err);
    };
    
    return () => {
      if (error.value) {
        return h('div', { class: 'error-boundary' }, [
          h('h3', 'Something went wrong'),
          h('p', error.value.message)
        ]);
      }
      
      return slots.default?.();
    };
  }
});
```

## 🌐 国际化开发规范

### 1. 基本原则

**禁止硬编码文本**
```vue
<!-- ❌ 错误 -->
<div>用户名</div>
<q-btn label="保存" />

<!-- ✅ 正确 -->
<div>{{ $t('user.username') }}</div>
<q-btn :label="$t('common.save')" />
```

### 2. 添加新文本流程

1. 在 `src/i18n/zh-CN.ts` 中添加中文键值
2. 在 `src/i18n/en-US.ts` 中添加对应的英文键值
3. 在组件中使用 `$t('key.path')` 引用
4. 运行 `npm run check:i18n` 验证

### 3. 键值命名规范

- 使用点分隔的路径：`module.submodule.key`
- 使用驼峰命名：`userProfile.editButton`
- 保持层级清晰，避免过深嵌套（不超过4层）
- 组件内专用的键可以使用组件名作为前缀

**示例：**
```typescript
// src/i18n/zh-CN.ts
{
  user: {
    profile: {
      editButton: '编辑个人资料',
      saveButton: '保存'
    }
  }
}

// src/i18n/en-US.ts
{
  user: {
    profile: {
      editButton: 'Edit Profile',
      saveButton: 'Save'
    }
  }
}
```

### 4. 开发工具

**国际化检查工具**

位置：`dev-tools/check-i18n.js`

使用方法：
```bash
npm run check:i18n
```

输出说明：
- ✅ 通过：所有使用的键都已定义
- ❌ 缺失中文：列出缺少中文翻译的键
- ❌ 缺失英文：列出缺少英文翻译的键
- ⚠️  不一致：列出中英文定义不一致的键

详细文档：[dev-tools/README.md](../dev-tools/README.md)

### 5. 会话结束检查清单 ⭐️

在每个开发会话结束时，**如果修改了页面文件（.vue/.ts）**，请确保：

- [ ] 运行 `npm run lint` 检查代码规范
- [ ] **运行 `npm run check:i18n` 检查国际化** 
- [ ] 修复所有 i18n 缺失的键值
- [ ] 确保中英文翻译都已完成
- [ ] 移除所有 `console.log` 调试代码
- [ ] 提交代码到版本控制

**注意：** 这是强制性要求，未通过 i18n 检查的代码不应提交。
